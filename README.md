# Cyber Payroll

## 项目简介

Cyber Payroll 本质上是一个基于本地 SQL 与 Python 的薪酬数据计算工具，目的是通过程序解决使用 Excel 计算薪酬时，由于数据来源杂乱、表格结构复杂以及业务逻辑多变而产生的大量重复和繁琐操作。

考虑到薪酬计算对数据本地化和隐私保护的要求，项目采用本地 SQLite 作为数据存储基础：先解析 Excel 文件表头和字段结构，在本地建立对应的数据库表；然后利用大模型理解用户通过自然语言描述的薪酬计算逻辑，协助设计计算思路并生成 Python 计算程序；最后导入完整的真实薪酬数据，由已经确认和发布的 Python 代码在本地完成计算。

在整个流程中，大模型只参与数据结构理解、计算思路设计和程序生成，不参与真实薪酬数据的最终计算。真实数据始终由本地 Python 程序读取、处理和写入结果，尽可能实现数据不出本地的初衷。同时，通过固定的 Python 代码执行核算，也能够最大程度保障计算过程的一致性和可追溯性，避免直接依赖 AI 进行数值计算时可能出现的幻觉、随机性和数据漂移。

面向个人学习与非商业使用的本地优先薪酬 / 提成核算工作台。

Cyber Payroll 试图把薪酬核算中最容易失控的部分——输入表结构、字段映射、核算逻辑、输出结果和操作记录——放进一个可追踪、可复用、可审计的本地工作流中。它不是一个把真实工资明细上传到云端的黑盒计算器，而是一个由本地 Python 和 SQLite 负责数据处理、由 React 页面负责配置与呈现、由 AI 负责辅助理解和生成建议的组织级核算工具。

> 当前项目处于持续开发阶段。请在正式使用前自行审查代码、核对核算规则，并使用脱敏数据进行完整验证。

## 项目定位

薪酬、提成、考勤和绩效数据通常来自多个 Excel 工作表，字段名称、数据类型、主键和业务规则也会随着组织和期间变化。Cyber Payroll 将这些内容拆分为可确认的 Schema、字段映射、关系、计算逻辑和输出配置，在本地完成数据检查、导入、计算、导出以及历史记录保存。

项目适合以下场景：

- 个人学习、研究和实验薪酬核算系统的设计与实现；
- 根据组织或业务场景保存独立的输入表、规则和输出模板；
- 对 Excel 输入文件执行导入前结构检查和导入后本地核算；
- 将核算逻辑、字段配置、版本元数据和审计记录一起保存；
- 使用兼容 API 的 AI 服务辅助理解表结构、生成或修复计算逻辑。

## 核心能力

### 组织级数据隔离

每个组织拥有独立的工作目录和业务数据边界。应用级数据库只保存组织索引；组织配置数据库保存 Schema、字段映射、核算逻辑、输出方案、配置版本和审计信息；组织业务数据库保存真实业务行、导入批次、核算运行和结果数据。

### 本地优先的数据导入

Excel 文件在导入前由本地 Python 检查工作表、标题范围、字段完整性、重复字段、主键和可转换类型。校验不通过时不应进入正式导入；正式导入按行转换并写入组织业务数据库，导入批次记录对应的 Schema 指纹，便于后续追踪。

### 可配置的核算模型

核算设计由输入 Schema、字段关系、临时计算字段、全局计算逻辑、输出字段规则和生成的 Python 代码共同组成。计算配置与真实业务数据分离，便于保存版本、重新计算、检查差异和迁移到其他组织。

### AI 辅助而非数据处理中心

AI 可用于理解 Excel 结构、辅助生成计算逻辑、提出修复建议和回答数据问题。核心数据导入、类型转换、核算执行和结果写入由本地 Python 完成。配置 AI 时支持 DeepSeek、智谱 GLM、ChatGPT / OpenAI 兼容接口以及自定义 HTTPS 兼容接口；使用任何外部模型前，都应自行确认供应商、网络请求范围和隐私政策。

### 历史与审计

项目保留导入批次、核算运行、配置版本和审计记录等信息，并支持将不含业务明细的配置与 Python 版本包导出，用于复盘核算配置和追踪变更。

## 页面结构

当前前端围绕以下工作流组织：

1. **总览**：查看当前组织、数据状态和核算摘要。
2. **输出目标**：确认输出表结构、字段顺序和输出字段规则。
3. **数据**：维护输入数据表、字段映射、主键和期间配置。
4. **核算设计**：维护关系、临时字段、全局逻辑和生成的核算代码。
5. **数据导入**：检查 Excel 结构，导入已确认的数据文件。
6. **历史 / 审计**：查看核算运行、配置版本、导入批次和操作记录。

## 技术结构

- **前端**：React、Vite、`lucide-react`、`xlsx`
- **后端**：Python 标准库、本地 HTTP API
- **数据存储**：SQLite
- **计算执行**：本地 Python 核算引擎与受限代码执行模块
- **导出**：Excel 结果文件与配置 / Python 版本包
- **默认地址**：前端 `http://127.0.0.1:5173`，后端 `http://127.0.0.1:8787`

## 快速开始

### 环境要求

- Python 3；
- Node.js 和 npm；
- macOS、Windows 或其他能够运行 Python 与 Node.js 的本地环境。

### macOS

在项目根目录执行：

```bash
./start_payroll.command
```

也可以分别启动前端和后端：

```bash
npm install
npm run dev
python3 -m backend.payroll_app.local_api
```

### Windows

双击项目根目录下的 `start_payroll.bat`，或在终端中执行：

```bat
start_payroll.bat
```

Windows 需要预先安装 Python 3 和 Node.js，并确保 `py` 或 `python`、`npm` 已加入系统 PATH。

启动后，在浏览器打开：

```text
http://127.0.0.1:5173
```

首次启动时，如果项目没有 `node_modules`，启动脚本会尝试执行 `npm install`。

## 数据与隐私边界

Cyber Payroll 的设计原则是：真实薪酬和提成明细优先留在本地组织数据库中，前端只呈现必要的结构、状态、摘要和审计信息。使用 AI 功能时应坚持最小化发送原则，不要把完整工资表、身份证号、银行卡号或其他敏感个人信息直接发送给外部模型服务；正式业务使用前，请根据实际部署方式重新审查所有 API 请求和数据流。

项目中的 `app_config.db`、组织目录、业务 SQLite 数据库、导出的 Excel 结果和配置文件可能包含敏感信息。不要将真实业务数据、API 密钥、个人信息或生产导出文件提交到公共 GitHub 仓库。建议在公开仓库中只保留代码、脱敏示例、结构说明和不含秘密的配置模板。

## 开发提示

前端开发服务器：

```bash
npm run dev
```

前端生产构建命令：

```bash
npm run build
```

后端主要模块包括：

- `local_api.py`：本地 HTTP API 与路由；
- `data_importer.py`：数据导入和本地校验流程；
- `template_inspector.py`：Excel 模板与字段结构检查；
- `calculation_engine.py`：核算执行；
- `organization_db.py`：组织配置、业务数据库和审计数据访问；
- `model_package.py`：核算模型包和版本元数据；
- `safe_python.py`：核算代码的受限执行支持；
- `ai_*.py`：AI 配置、结构建议、逻辑生成和数据问答辅助。
